# Fix Plan: AI Server Hardening (2026-08-06)

## Overview

Comprehensive fixes for security, reliability, performance, and maintainability issues
identified in the project analysis. Each fix is a self-contained slice that can be
implemented and tested independently.

---

## Phase 1: Critical Security & Reliability

### 1.1 ChromaDB Version Pinning + Persistence

**Problem:** ChromaDB v1.5.x has critical CVEs (pickle RCE #6926, unbounded HNSW #7225)
and silent data loss on clean exit (#6975).

**Fix:**
- Pin `chromadb>=0.5.0,<1.5.0` (last safe version before CVEs)
- Add explicit `_persist()` call after relationship saves
- Add `_persist()` in shutdown hook

**Files:** `ai-server/pyproject.toml`, `ai-server/chimera/memory.py`

### 1.2 Authentication + Localhost Binding

**Problem:** All endpoints open to network, CORS allows `*`.

**Fix:**
- Add `X-API-Key` header validation middleware
- Bind to `127.0.0.1` by default (configurable via env)
- Restrict CORS to localhost origins
- Disable docs/redoc in non-debug mode

**Files:** `ai-server/main.py`, `ai-server/chimera/config.py` (new)

### 1.3 Lifespan Handler + Graceful Shutdown

**Problem:** No lifecycle management, no flush on Ctrl+C.

**Fix:**
- Replace deprecated `@app.on_event` pattern with `lifespan` context manager
- Initialize shared httpx client on startup
- Flush ChromaDB + relationships on shutdown
- Add structured exception handlers

**Files:** `ai-server/main.py`

### 1.4 Reuse httpx.AsyncClient

**Problem:** New client per request = zero connection pooling.

**Fix:**
- Create one `httpx.AsyncClient` at startup, store on `app.state`
- Share across `check_ollama_available()` and `generate_action()`
- Close on shutdown

**Files:** `ai-server/chimera/llm.py`, `ai-server/main.py`

## Phase 2: Logic Fixes

### 2.1 Few-Shot Prompt Examples

**Problem:** Small models (phi3:mini) need examples to produce valid JSON.

**Fix:**
- Add 2-3 example input/output pairs to `system.txt`
- Include correct and incorrect examples
- Ensure JSON schema is prominently placed

**Files:** `ai-server/chimera/prompts/system.txt`

### 2.2 Directional Relationship Scores

**Problem:** `update_relationship()` mirrors scores — A liking B forces B to like A.

**Fix:**
- Store `(from, to)` as independent keys
- Update only the specified direction
- Maintain backward compatibility with existing persistence

**Files:** `ai-server/chimera/memory.py`

### 2.3 Rule-Based Fallback Hardening

**Problem:** NPC ID parsing breaks for non-numeric IDs, no time awareness.

**Fix:**
- Parse room from `npc_id` suffix safely with fallback
- Add time-of-day logic (morning=kitchen, night=bedroom)
- Handle empty/missing fields gracefully

**Files:** `ai-server/chimera/llm.py`

### 2.4 Event Injection Validation

**Problem:** No length limit, records to all NPCs regardless of room.

**Fix:**
- Add `max_length=500` to `EventInjectRequest.text`
- Scope memory recording to NPCs in target room when specified
- Add rate limiting (max 10 events per minute)

**Files:** `ai-server/chimera/models.py`, `ai-server/chimera/game_master.py`

## Phase 3: Developer Experience

**Problem:** `uv.lock` gitignored (breaks reproducibility), no pip fallback.

**Files:** `.gitignore`, `ai-server/requirements.txt` (new)

### 3.2 Fix verify_server.py
